# Core Terrain Patches

A terrain patch is a polygon drawn by the user (usually snapped to the edges of roads and intersections) and filled with a textured, triangulated surface. Patches can have internal points (to shape hills) and **border meshes**: road-like meshes generated along part of the outline, such as walls and railings.

The surface itself is generated by the program; the core defines the patch parameters, the UV scale, and the border mesh types.

```
terrainPatches/
├── terrainPatches/<type>/
│   ├── ui.json
│   ├── parameters.json
│   └── settings.json
└── borderMeshes/<type>/
    ├── ui.json
    ├── parameters.json
    ├── settings.json
    └── components/<component>.json      (or in elements/sharedComponents/)
```

## Terrain patch types

### `parameters.json`

Same format as for other elements (see [Parameters and UI](Parameters-and-UI)). Patches have no per-section evaluation, so only static definitions are meaningful. Required definitions:

| Variable | Description |
|---|---|
| `uMult`, `vMult` | UV scale: the UVs of the surface are the world X and Z coordinates multiplied by these values. |

Patch parameters cannot be `instanceSpecific`. Built-in state properties (edited in `mainGroup`): `type`, `texture` (the surface texture; an empty texture makes the patch invisible), `smooth` (smoothing iterations of the internal vertices) and `projectToGround`.

Terrain patches have no presets: a new patch gets the first terrain patch type (in folder order), the last texture used, projection enabled, no smoothing, and every core parameter at its zero value (0, false, empty). Choose parameter meanings so that these values are a sensible default.

The MM2 core uses patch parameters only for its exporter (block number, merging connected patches, perimeter-only patches...): every parameter is part of the patch state in the exported file, whether or not it affects the geometry.

### `settings.json`

```json
{
    "borderMeshTypes": ["psdl"],
    "borderMeshName": "Rail",
    "maxBorderMeshes": 15
}
```

| Key | Description |
|---|---|
| `borderMeshName` | Text used to name the border meshes in the list (`Rail 1`, `Rail 2`, ...). It is used as is, not as a string key. |
| `maxBorderMeshes` | Maximum number of border meshes per patch (0 for no limit). |
| `borderMeshTypes` | Intended list of border mesh types usable with this patch type. Currently not enforced: the border mesh panel lists all border mesh types. |

### `ui.json`

Built-in groups: `mainGroup` (type, point placement mode, last point deletion, smoothing, projection, auto-close, texture) and `borderMeshGroup` (border mesh list, placement, add, remove, edit). Without `borderMeshGroup` users cannot create border meshes.

## Border meshes

A border mesh type has exactly the same format as a road type (see [Core Roads](Core-Roads)): `settings.json` with `sectionVertices`, `anchors`, `components`, `textures`, `texturesMapping`; `parameters.json`; `ui.json` with a `mainGroup` element (type and preset selection). It is generated along the sequence of perimeter points selected by the user, with one section per point.

Differences from roads:

* The sections are the selected points themselves, without curve sampling or projection. The points are always ordered clockwise around the patch (seen from above), so `localRight` points **outside** the patch.
* `sectionVertices` still offset the `v<n>` vertices along `localRight`. The MM2 core sets them all to `0` and builds everything from `v0`, `localUp` and `localRight`.
* There are no intersections: `hasStartIntersection`, `throughIntersection`, `startIntersectionPosition` and the other intersection-related variables are 0. `totalLength` is the length of the selected outline and `segments` the number of selected points.
* Traffic lanes, props lines, anchors and parametric objects are not generated. In `settings.json`, `trafficTypes`, `trafficLanes`, `propsLines`, `propsContainers`, `getters`, `widths` and `anchors` can be omitted.
* Since components can be shared, the same component files can be used by roads and border meshes (MM2 uses `rail_rail_left` and `rail_wall_left` in both), as long as the variables they use exist in both types.

Border meshes have their own state (presets category `terrainPatchBorderMesh`) and instance state, so `instanceSpecific` parameters are allowed. Container presets (`PRESET_<container>`) work as for roads.

## Automatic generation

"Create whole city terrain" creates one patch for each area enclosed by roads and intersections (by following their anchor chains, see [Core Roads](Core-Roads#settingsjson) and [Core Intersections](Core-Intersections#junction-files)) and a ring of patches around the whole road network. The new patches are created like manual ones (see above), with the texture, smoothing and internal point distance chosen in the dialog. The quality of the result depends on the anchors of the core's road and junction types: they must form closed loops around every block.
